## 2. 후보 생성 품질: 20 mm 격자 전수탐색 오라클 (`reports/oracle_benchmark.json`)

같은 Hard Mask로 20 mm 격자의 모든 위치(두 yaw)를 검사한 결과와 5-① 후보를 비교했습니다(가상 장면 100개).

| 지표 | 값 |
|---|---|
| 격자에 놓을 자리가 있는 장면 | 78 |
| 그중 5-①이 유효 후보를 1개 이상 제공 (**재현율**) | **76/78 = 97.4 %** |
| 격자에는 없는데 5-①만 찾은 장면 | 0 |
| 최저 윗면 높이: 5-① − 격자 | 평균 −6.5 mm (5-①이 더 낮음), 최대 +53.7 mm (1장면) |
| 5-①이 격자보다 같거나 좋은 비율 | 96.1 % |
| 후보 수 (생성 / 유효) | 47.4 / 12.6 |
| 5-①+② 계산 시간 | 평균 13.9 ms, p95 25.0 ms |

- 놓친 2장면은 격자에서도 놓을 자리가 1개뿐인 경우입니다. 무거운 박스가 가벼운 박스 여러 개에 하중을 나눠야만(`share`) 놓일 수 있는, 40 mm보다 좁은 자리입니다.
  같은 층까지 훑으면 1장면을 더 찾지만 동한 님 planner의 1초 초과가 3 → 5건으로 늘어 채택하지 않았습니다. 이전 `per_box` 기준 재현율은 100 %였습니다.
- 53.7 mm 차이 장면은 격자에 놓을 자리가 742개나 있는 장면으로, 5-①이 고른 가장 낮은 후보가 격자보다 한 층 높았던 경우입니다(안전 문제는 아님).

## 3. Hard Mask의 물리 타당성: 재성 님 PyBullet 시뮬레이터 (`reports/physics_*.json`)

장면 60개에서 후보를 골라 **실제 크기**(측정 노이즈 전) 박스를 계획 위치에 놓았습니다.
1.0초 정착 후 1.5초를 관찰했고, 이동 10 mm 또는 기울기 2° 초과면 불안정으로 판정했습니다.

| 그룹 | solid 팔레트 | slatted 팔레트 |
|---|---|---|
| Hard Mask **통과** 후보 | **82/82 안정 (100 %)** | **82/82 안정 (100 %)** |
| 지지율/LBCP로 **탈락**한 후보 (대조군) | 42/110 안정 → **62 % 실제로 붕괴/이동** | 동일 |

- 통과 후보는 하나도 무너지지 않았습니다 → **안전**.
- 탈락 후보의 약 2/3는 실제로 무너졌습니다 → 마스크가 **의미 있는** 경계를 긋습니다.
- 탈락했지만 버틴 나머지는 CoG δ와 지지율 70 % 기준으로 보수적으로 거른 경우입니다. 강체 시뮬레이션은 골판지 변형이나 내용물 편심을 반영하지 않습니다.

## 4. 동한 님 planner(5-③~⑥) 연동 (`reports/planner_benchmark.json`)

가상 장면 30개(유효 후보가 있는 장면 23개)에서 `PlacementPlanner.plan()`을 1초 소프트 예산으로 실행했습니다.

| 지표 | 값 |
|---|---|
| 계획 시간 | 평균 765 ms, p95 1073 ms, 최대 1300 ms |
| 예산 초과 (소프트) | 7/23 (리뷰 수정 전 3/24) |
| 시나리오 7개 모두 완료 | 13/23 |
| 예산 때문에 축소(K/시나리오/horizon) | 11/23 |
| `EMS_SUPPLIED` 특징 비율 | 100 % |
| 최종 1순위 후보 재검증 | 모두 통과 |

시간은 대부분 5-③ 특징 계산의 잔여재고 프로브(유효 후보 × SKU 수만큼 생성기 호출)에서 씁니다. 마지막 수정(중복 제거에서 가려진 후보 복원)으로 후보 다양성이 늘어 프로브가 조금 늘었습니다(689 → 765 ms). [interface.md](interface.md) 8장의 제안을 참고하세요.
느린 하드웨어에서는 1초 예산을 넘을 수 있으므로 실제 운영 PC에서 다시 측정해야 합니다.

## 8. 박스 강도 사양 비공개 대응: 숨겨진 실제 강도 시나리오 (`reports/strength_sweep.json`, `reports/full_pallet_summary.md`)

사양이 없으므로 실제 강도를 6개 프로필(strong, nominal, weak, humid, mixed, extreme)로 생성하고 planner에는 숨겼습니다.
planner는 가정 허용하중(McKee/안전계수)만으로 적재하고, 최종 팔레트를 실제 강도로 다시 계산했습니다.
데이터는 시나리오당 80박스, 12개 시나리오(프로필당 2개)입니다.

| 가정 안전계수 | 적재율 | 평균 높이 | 실제로 눌린 박스 | 최대 실제 하중비 |
|---|---|---|---|---|
| 1 (여유 없음) | 51.7 % | 1.14 m | 0 | 0.96 |
| 2 | 51.7 % | 1.14 m | 0 | 0.96 |
| **4 (기본값, 확정)** | **51.5 %** | **1.13 m** | **0** | **0.96** |
| 8 | 49.7 % | 1.05 m | 0 | 0.96 |
| 16 | 44.1 % | 0.82 m | 0 | 0.72 |

- **6개 프로필 모두, 안전계수 1에서도 실제로 눌린 박스가 0개**입니다(최대 하중비: extreme 0.96, weak 0.93, 나머지 0.20~0.68).
- 리뷰 수정 전에는 extreme에서 3개(`per_box` 시절 7개)가 눌렸습니다. 하중을 지지 박스의 받칠 수 있는 부분으로만 전달하고, `share` 모드에서 모든 지지 박스를 검사하도록 고친 효과입니다.
- 검사에서 놓친 파손 박스는 여전히 가정값으로 막기 어려운 위험이며 2단계 검사가 담당합니다. 검사가 찾은 파손 박스 위에는 모든 실험에서 아무것도 쌓이지 않았습니다.
- 결론: 기본값(안전계수 4)은 극단 외 모든 경우에서 안전하고 적재 손실이 없습니다. 박스가 매우 약할 것으로 의심되면 안전계수 8~16(`config/taehyeon/candidates.yaml`의 `load_model.safety_factor`)으로 올립니다.

## 10. 무거운-위-가벼운 규칙: `per_box` → `share` (태현 결정, 2026-10-08)

**근거 문구**: 주최측(HD현대로보틱스) 과제 1 설명서 "필수 고려사항"의 "무거운 박스가 가벼운 박스 위에 적재되지 않도록 **하중 제약** 반영"입니다(팀 흐름도 5-②에는 없음).
구체적인 판정식은 문구에 없어서 팀이 정합니다. `per_box`는 문구를 글자 그대로(바로 아래 박스 하나하나와 무게 비교), `share`는 "하중 제약"으로(각 박스가 실제로 받는 하중 비교) 해석한 것입니다.

`per_box`(무거운 박스는 직접 받치는 박스 하나하나보다 가벼워야 함)는 박스가 무작위 무게 순서로 오면 높이 쌓기 어렵습니다.
`share`는 각 지지 박스가 **실제로 받는 무게**(새 박스 무게 × 하중 분배 비율)로 비교합니다. 무거운 박스가 가벼운 박스 여러 개에 걸치면 허용될 수 있습니다.
박스 허용하중(McKee) 검사는 두 모드 모두 그대로 적용됩니다.

**4번 시뮬레이션** (박스 80개 흐름, 버퍼 4칸, Rule 정책, val 시나리오; 위치는 DBLF 또는 동한 님 planner)

| 규칙 | 사용 팔레트 (DBLF, 9개) | 채움률 | 사용 팔레트 (동한 님 planner, 4개) | 채움률 |
|---|---|---|---|---|
| `per_box` 1.0 | 5.12 | 20.7 % | 4.85 | 22.7 % |
| `per_box` 1.5배 허용 | 3.44 | 29.6 % | 3.77 | 29.0 % |
| `per_box` 2.0배 허용 | 3.04 | 33.2 % | — | — |
| **`share` (채택)** | **4.07** | **25.5 %** | — | — |
| 규칙 끔 (참고) | 2.70 | 36.2 % | 3.25 | 33.6 % |

**실제 강도 기준 눌림** (팔레트 1개를 80박스로 채우는 12개 시나리오, 안전계수 4)

| 규칙 | 적재율 | 평균 높이 | 눌린 박스 (전체 / extreme 외) |
|---|---|---|---|
| `per_box` 1.0 | 51.5 % | 0.95 m | 7 / 0 |
| `per_box` 1.5배 | 63.6 % | 1.24 m | 12 / 2 |
| `per_box` 2.0배 | 69.4 % | 1.30 m | 20 / 2 |
| **`share`** | **54.4 %** | **1.09 m** | **3 / 0** |
| 규칙 끔 | 69.7 % | 1.30 m | 20 / 0 |

- `share`는 팔레트를 약 20 % 덜 쓰면서 눌림이 늘지 않아 채택했습니다. 1.5배 이상 완화하거나 끄면 팔레트는 더 줄지만 일반 강도 박스(mixed, weak)에서도 눌림이 생깁니다.
- 시나리오가 프로필당 2개라 눌림 숫자는 흔들림이 큽니다. 미션 문구("무거운 박스를 가벼운 박스 위에 금지")에 가장 가까운 것은 `per_box`이며 설정 한 줄(`heavy_on_light.mode`)로 되돌릴 수 있습니다.
- 동한 님 planner를 위치 결정에 써도 `per_box`의 채움률은 23 %로 비슷했습니다. 낮은 채움률의 원인은 위치 결정 방식이 아니라 규칙이었습니다.
